# DEAi Lark ↔ SAP HANA Bridge

**Developer:** Uzziah Drej M. Ferrer 
**Date:** September 7, 2026

## 1. Project Overview
This repository contains the source code for the DEAi chatbot, which bridges Lark messaging with an SAP HANA database. It allows users to query live SAP data (sales, stock, aging invoices, and general ledger expenses) using both explicit slash commands (e.g., `!sales`, `!report`) and natural language queries (`!ask`). The bot translates natural language into secure SQL, fetches the data, and returns conversational insights alongside dynamic UI cards.

## 2. Tech Stack & Dependencies
*   **Language:** Python
*   **Platform Integration:** Lark Open API (`lark_oapi`) using WebSocket
*   **Database Integration:** SAP HANA DB API (`hdbcli`)
*   **AI / LLM Providers:** Supports Groq, Google Gemini, Anthropic, and OpenAI
*   **Environment:** Configured via `.env`

## 3. Core Modules & Architecture
*   **`main.py` (The Orchestrator):** The primary entry point that handles Lark WebSocket events. It enforces per-user rate limits, deduplicates messages, and routes commands to the appropriate handler. It utilizes a single-instance lock to prevent duplicate bots from running.
*   **`ai_router.py` (The AI Engine):** Manages the LLM abstraction layer. It defines two roles: a "ROUTER" for fast natural language intent classification/query planning, and an "ANALYST" for generating grounded, qualitative executive summaries from the retrieved SAP data.
*   **`database.py` (The Data Access Layer):** Handles all SAP HANA connections. It executes predefined queries (e.g., top clients, sales, aging) and dynamically compiles and executes JSON query plans generated by the AI. 
*   **`lark_ui.py` (The Presentation Layer):** Converts plain text and Markdown into Lark interactive cards. It includes logic to detect tabular data and automatically generate VChart JSON specifications (bar charts) based on the most relevant numeric columns.
*   **`config.py` (The Configuration Hub):** Centralizes all environment variables, LLM provider selections, temperature tunables, and database connection settings. 

## 4. Security & Safeguards
*   **Zero-Trust Read-Only SQL:** `database.py` enforces a strict read-only policy. It validates queries against an allowed schema and explicitly blocks destructive keywords (e.g., `INSERT`, `UPDATE`, `DELETE`, `DROP`).
*   **Circuit Breaker:** The database module includes a circuit breaker that locks queries for a cooldown period (300 seconds) if failure thresholds are met, protecting the SAP HANA instance from being overwhelmed.
*   **LLM Hallucination Prevention:** The AI Analyst is strictly bounded. It builds deterministic Markdown tables in Python and verifies record counts and totals using code *before* passing the data to the LLM, ensuring the AI cannot invent or hallucinate financial figures. 

## 5. R&D and Utility Scripts
*   **`find_expense_tables.py`:** An exploratory script used to query `OUTB` and `OCRD` to map custom User-Defined Tables (UDTs) and vendors related to expenses/claims.
*   **`convert_cert.py`:** A utility that converts the SAP HANA server certificate from DER (`hana_server.cer`) to PEM format (`hana_server.pem`).
*   **`test_connection.py`:** A standalone diagnostic tool to verify SAP HANA certificate validation and database connectivity prior to launching the full bot.
